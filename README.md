Нативная утилита macOS: запускайте Flutter-проекты, делайте Hot Reload и читайте логи без перехода в Terminal или IDE.

## Установка

[**Скачать SimFlutDock 1.0.8 (.dmg)**](https://github.com/Shishani58/Fluttios/releases/download/v1.0.8/SimFlutDock-1.0.8.dmg)

Нужны **macOS 14+**, **Flutter SDK** и полный **Xcode**. Поддерживаются Apple Silicon и Intel. Откройте DMG и перетащите приложение в **Applications**.

Сборка не нотарифицирована Apple; при блокировке первого запуска следуйте [инструкции Apple](https://support.apple.com/ru-ru/102445).

### Обновления

Приложение проверяет стабильные GitHub Releases при запуске, не чаще раза в сутки. Проверить вручную можно через **Настройки → Общие → Обновления приложения**. Автоматическую проверку можно отключить.

При ручном нажатии **Проверить обновления…** новая версия сразу скачивается и подготавливается. Фоновая проверка только сообщает о новой версии: скачивание начинается по кнопке **Скачать обновление**. Приложение проверяет размер, SHA-256, версию и подпись, затем предлагает **Закрыть и установить**. После подтверждения SimFlutDock закрывается, автоматически заменяет установленную копию и запускается снова. Работающие сессии Flutter останавливаются с подтверждением; отмена выхода откладывает установку. Скачивание можно отменить. Для автоматической замены приложение должно находиться в доступной для записи папке, вне DMG; при ошибке замены сохраняется предыдущая версия.

Для выпуска обновления опубликуйте стабильный релиз `vX.Y.Z` с файлами `SimFlutDock-X.Y.Z.dmg` и `SimFlutDock-X.Y.Z.dmg.sha256` и `app-update.json`. Их создаёт `scripts/build-dmg.sh` и публикует существующий workflow. Номер версии должен быть выше установленного; предварительные релизы не предлагаются.

## Главное

- **Run, Hot Reload, Hot Restart и Stop** — отдельная сессия для каждой пары «проект + устройство». Переключение устройства меняет управляемую сессию, сохраняя остальные запуски.
- Панель рядом с **Simulator / Device Hub** или в свободном положении.
- Выбор устройств и режимов запуска, поддержка **FVM**.
- Логи, сохранённые deep links, быстрый доступ к папкам проекта и приложения.
- Русский и английский интерфейс, светлая и тёмная темы.

## Быстрый старт

1. Откройте SimFlutDock → иконка в строке меню → **Настройки → Проекты → Открыть проект**. Выберите папку с `pubspec.yaml`.
2. Выберите устройство и нажмите **Run**. После изменения Dart-кода используйте **Reload**, для сброса состояния — **Restart**.
3. Для привязки панели разрешите SimFlutDock в **Настройках системы → Конфиденциальность и безопасность → Универсальный доступ**.

Hot Reload и Hot Restart работают в Debug. После изменения нативного кода или плагинов используйте **Stop → Run**.

### Память и фоновые процессы

`dart:frontend_server_aot.dart.snapshot` — компилятор Flutter для Debug и Hot Reload. `Runner` — запущенное приложение, а `SimMetalHost` и `SimRenderServer` — службы графики симулятора iOS. Их память учитывается отдельно от SimFlutDock. **Stop** завершает сессию Flutter и оставшиеся процессы в принадлежащей ей группе; сам симулятор остаётся включённым. Если он больше не нужен, выключите конкретное устройство командой `xcrun simctl shutdown <UDID>`.

SimFlutDock хранит не более 2000 строк и 2 МиБ текста журнала на сессию, обрезая отдельную запись примерно до 16 КиБ. Старые записи удаляются первыми. Удаление неактивного проекта освобождает все его сессии и журналы. Это ограничения текста журналов, а не всей памяти приложения.

## Сборка из исходников

```bash
git clone https://github.com/Shishani58/Fluttios.git
cd Fluttios
APP_OUTPUT=/Applications/SimFlutDock.app ./scripts/build-app.sh
open /Applications/SimFlutDock.app
```

Команда обновляет одну установленную копию в Applications. Для отдельной сборки без установки используйте `./scripts/build-app.sh`; результат в `dist` не нужно устанавливать повторно. Для сборки DMG: `./scripts/build-dmg.sh`.

Проверки, структура исходников и интеграционные тесты описаны в [Contributing](CONTRIBUTING.md).
