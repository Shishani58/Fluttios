# Ревью SimFlutDock

Дата: 16 октября 2026 года.

Проверены исходники macOS-приложения, Core, login helper, тесты, Xcode-проект, скрипты сборки, workflow релиза и документация. Найденные ниже ошибки исправлены в рабочей копии. Ранее начатые изменения автоматической установки обновлений включены в проверку и сохранены.

## Исправленные ошибки

| Приоритет | Проблема и последствие | Исправление и проверка |
| --- | --- | --- |
| P2 | После остановки Flutter-сессий ошибка запуска установщика отменяла выход, но оставляла `SessionManager.shuttingDown = true`. Следующие нажатия Run игнорировались. | При отмене завершения после неудачной передачи установщику снимается блокировка запуска. `testCancelledShutdownAllowsNewLaunches` проверяет новый запуск после отмены завершения. |
| P2 | Завершение Hot Reload / Hot Restart проверяло только наличие процесса и отсутствие остановки. Если соединение уже потеряно, позднее завершение могло вернуть состояние Running. | Завершение привязано к поколению процесса и исходному состоянию операции. `testRestartFailureCannotRestoreRunningStateAfterDisconnect` проверяет, что отключённая сессия не возвращается в Running. |
| P2 | Подготовка обновления вызывала `hdiutil`, `ditto` и `codesign` через синхронный `waitUntilExit`, без тайм-аута и прерывания выполняемой команды. | Команды используют `ToolRunner`, тайм-ауты и отмену. Размонтирование выполняется отдельной задачей очистки даже при отмене. Проверены подготовка настоящего тестового DMG, отказ проверки подписи, ранняя отмена и существующие тесты отмены/тайм-аутов процессов. |
| P2 | Закрытый клиент machine protocol принимал новые запросы. После закрытия транспорта они могли ждать тайм-аута. | Закрытие сохраняет ошибку и немедленно отклоняет последующие запросы без записи в транспорт. `testClosedClientRejectsRequestsWithoutWritingOrWaitingForTimeout` проверяет это поведение. |
| P3 | Интеграционный тест выбирал любые устройства со статусом Booted, включая Android-эмуляторы. | Выбор ограничен iOS Simulator, как требует сценарий теста. |
| P3 | Английский README описывал ручную установку DMG, а русский — новую автоматическую замену приложения. | Описания синхронизированы; в SECURITY добавлено описание сетевых запросов обновления. |

## Поддерживаемость

- `Views.swift` разделён на `PanelView`, `ProjectMenu`, `DeviceMenu`, `SettingsView`, `LogsView` и `ViewSupport`. Общие компоненты имеют внутреннюю видимость модуля, локальные детали остались private. Xcode-проект и проверка версии обновлены.
- Классы из `CoreTests.swift` перенесены в отдельные файлы по областям проверки.
- Все Swift-файлы приведены к `.swift-format`: отступ 4 пробела, длина строки 120. Поля GitHub JSON сопоставляются через `CodingKeys` с именами Swift в camelCase.
- Добавлены `scripts/check.sh`, CI на push и pull request и `CONTRIBUTING.md` с командами проверки и описанием границ модулей.
- Короткие команды инструментов получают закрытый стандартный ввод и не ждут интерактивного ввода приложения.

## Перед выпуском

Для проверки выпуска остаются реальный Run / Reload / Restart двух Flutter-проектов, физические устройства, запуск на macOS 14 и Intel и установка обновления из запущенной пользовательской копии. Автоматические тесты проверяют подготовку DMG и замену/откат на изолированных файлах; текущее установленное приложение не заменялось. Действующие ограничения notarization и частных WindowServer API описаны в README и SECURITY.
